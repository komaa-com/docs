This is a self-contained Teams CVI plugin for **OpenClaw**. It depends only on the
published `openclaw` plugin-sdk + `api.runtime` - no fork, no vendored runtime.

<Note>
  This adds **voice/video (CVI)** on top of OpenClaw's existing
  [Microsoft Teams chat channel](https://docs.openclaw.ai/channels/msteams) - run both for chat + calls.
</Note>

## Requirements

- An **OpenClaw** install - host **≥ `2026.6.9`**.
- A **StandIn** subscription ([standin.komaa.com](https://standin.komaa.com), free package) - the
  hosted media bridge that joins the Teams call and connects to this plugin. See
  [Architecture](/concepts/architecture).
- **Realtime mode:** a realtime voice provider + key. **Streaming mode:** your openclaw-configured
  STT / TTS / agent (no realtime key needed).

## Install

```bash
openclaw plugins install npm:@komaa/openclaw-msteams-bridge
```

The package ships **prebuilt** (v0.1.10+): no build step, install and go.

<Note>
  The two registries carry different names. On **npm** it is `@komaa/openclaw-msteams-bridge` - the
  install above. On **ClawHub** the listing is `@komaa/msteams-bridge`:
  `openclaw plugins install clawhub:@komaa/msteams-bridge`. Either path installs the same plugin under
  the id `msteams-bridge`, so the configuration is identical. See the
  [plugin README](https://github.com/komaa-com/openclaw-msteams-bridge#install).
</Note>

## Verify

Once installed, enable it in your config (`plugins.entries."msteams-bridge".config.enabled: true`) and
start the gateway:

```bash
openclaw gateway run
```

The plugin registers a host-managed service and binds the **calling** listener on `9442`. Teams chat
is not this plugin: it is OpenClaw's own `msteams` channel, on its own port. A full connection needs
both of these reachable:

| Public path | Lane | Local target |
|---|---|---|
| `/msteams/calling` | the media WebSocket StandIn dials, one connection per call | `127.0.0.1:9442`, path `/msteams/calling` (this plugin) |
| `/api/messages` | Teams chat to and from your agent | `127.0.0.1:3978`, path `/api/messages` (OpenClaw's `msteams` channel, `channels.msteams.webhook.port`) |

Voice-only? Mount the calling path alone - leaving `3978` unexposed simply means nothing posts chat to
you.

## Expose the lanes

StandIn connects to your agent **from the internet**, so both paths must be reachable - a public host,
or a tunnel. The mount commands, the probe recipes, and the values you register live in one place:

<Card title="Expose your agent" icon="globe" href="/expose">
  The two mount commands for OpenClaw (`9442` for voice, `3978` for chat), how to check a mount
  actually works, and what to paste into the StandIn dashboard.
</Card>

Mount each path onto your public host with the target path repeated, then register the resulting
`wss://<machine>.<tailnet>.ts.net/msteams/calling` (with a **matching `secret`**) in the
[StandIn sandbox](https://standin.komaa.com/sandbox) or on your identity in the
[dashboard](https://standin.komaa.com/dashboard). Add
`https://<machine>.<tailnet>.ts.net/api/messages` as the **Agent chat URL** if you want chat, then
place a Teams call to your bot. With path mounts neither public URL carries a port.

<Note>
  **Probing the voice path by hand? Pass `--http1.1`.** Through a funnel, curl without it sends a plain
  GET and gets a `404` that looks exactly like a missing mount. A live OpenClaw answers a real upgrade
  on the bare path with `400 Bad Request (missing callId)`, which means the plugin is healthy. Full
  details on [Expose your agent](/expose#probe-it-by-hand).
</Note>

<Note>
  Funnel serves up to 3 external ports (443, 8443, 10000), which is why path routing is the better
  default: every lane can share 443. Running the **Hermes** plugin on the same machine? Give it its own
  paths on the same host and its own local calling port (both plugins default to `9442`, so move one
  of them: `port` on OpenClaw, `calling_port` on Hermes), and register each runtime as its own agent
  with its own secret.
</Note>

<Note>
  Using the **StandIn Managed Bot** with the plugin's managed chat lane? That mode uses a different
  chat path and port (`/msteams/messages` on `9444`) instead of `/api/messages` - see
  [Managed bot chat](/expose#managed-bot-chat-uses-a-different-path). The one-line installer sets it
  up for you with `--connection managed --runtime openclaw` and the connection secret from the
  dashboard: [Quickstart: StandIn Managed Bot](/quickstart#standin-managed-bot).
</Note>
